# Aprendizados

## O que eu fiz
Neste projeto, criei um guia de cibersegurança para iniciantes em Markdown e usei Git e GitHub para organizar, versionar e publicar o material.

## O que aprendi sobre Git e GitHub
- Branches permitem trabalhar em partes diferentes do projeto sem mexer direto na `main`.
- Commits pequenos e com mensagens claras facilitam entender o histórico.
- Pull requests ajudam a revisar o que foi feito antes de integrar.
- Conflitos de merge acontecem quando a mesma linha é alterada em lugares diferentes, e é preciso decidir qual versão manter.

## Dificuldades
- Entender a diferença entre a main, as branches locais e as branches no GitHub. No começo, eu não entendia por que os arquivos da pasta docs/ sumiam quando eu voltava para a main, nem por que uma branch aparecia no meu computador e depois também no GitHub.

## Como resolvi
- Passei a usar git branch e git status antes de cada passo para saber em qual branch eu estava.
- Percebi que cada branch guarda a sua própria versão dos arquivos, e que os arquivos voltam quando a branch é integrada na main, como aconteceu depois do merge e do git pull.
- Entendi que o git push envia a branch do meu computador para o GitHub e que o git pull traz de volta as mudanças feitas lá, como o merge dos pull requests.

## O que eu faria diferente
- Planejaria os nomes das branches e a ordem dos commits antes de começar.
- Conferiria sempre em qual branch estou antes de criar ou alterar arquivos.
- Abriria o pull request mais cedo, para revisar o trabalho aos poucos.

## Conclusão
Com este projeto, entendi que o versionamento organiza o trabalho e mostra como o projeto foi construído, e não só o resultado final.
